Advanced Genie Editor 3 汉化说明（2026-10-02）
================================================

汉化对象：AdvancedGenieEditor3.exe（Advanced Genie Editor 2026.2.12）
          AGE3NamesV0007.ini（护甲 / 地形表 / 文明资源 名称表）
          AGE3Lang_zh.txt（中文语言文件：单位 / 科技 / 文明等名称）

一、汉化了什么
1. 主程序 AdvancedGenieEditor3.exe
   - 界面文字就地改写，共 3119 处、3116 条唯一文本（菜单、标签、按钮、下拉项、
     提示框、标题、下拉选项名）。
   - 文件大小与原始完全相同：10,115,072 字节；没有新增或删除任何节（section），
     只改写 .rdata 段内被程序真正引用的字符串字面量，因此不影响其它数据。
   - 实机验证：启动后抓取窗口文本 606 条唯一标签，其中中文 597 条、英文 9 条、
     乱码（U+FFFD / Latin-1 假字符）0 条。载入数据集后再抓取 610 条标签，
     中文 554 条；其余 56 条是数据自带的文明缩写（Ac、Br、Gaia...）与控件类名，
     不属于程序界面文字。
   - 第二轮续译：第一轮只覆盖了“启动时看得见”的文字，悬停提示（tooltip）、
     下拉列表的选项、消息框、对话框标题等只在交互瞬间出现的文字仍是英文。
     第二轮针对这些文字补译，新增 1672 处（覆盖悬停提示 tooltip、下拉列表选项、
     消息框与对话框标题/按钮等），连同第一轮累计 3119 处。
     每条译文都按“原文 -> 中文”逐条与已落盘字节比对，3119/3119 通过，
     差异字节 72923 个全部落在声明的改写区间内。
2. 名称表 AGE3NamesV0007.ini
   - 569 条名称全部译为中文：[AoE2DEArmorNames] 37 条、[AoE2DETerrainTableNames] 32 条、
     [AoE2DECivResourceNames] 500 条。
   - 行数 576 -> 581 行、CRLF 换行、无 BOM（11092 字节）；原有键名与段落顺序与原件一致。
   - 末尾多出的一节 [计数] 是给汉化版程序用的：汉化版把 ini 的组名/键名也一起汉化了
     （源码 Lists.cpp:990-995：KeyNumArmors = "Counts/Num" + KeyArmors + "Armors"）。
     若只保留英文键，汉化版读不到条目数，就会用内置默认名覆盖本文件的名称表。
     现在中英两套计数键并存，汉化版与原始英文版程序都能正确读到同一份中文名称表。

二、语言文件 AGE3Lang_zh.txt（怎么用）
   作用：让单位、科技、文明、地形等列表显示官方中文名（取自 AoE2DE 的 strings 语言表，
         合并 13 个表共 36351 条 —— 主表 key-value-strings-utf8.txt 只有 19677 条，
         新 DLC 的名称另外放在 key-value-paphos-strings-utf8.txt 等表里）。
   用法（推荐）：
     1) 启动 AGE3，在「打开 文件...」对话框里勾选「语言文件位置」；
     2) 点该行右侧「浏览」，选择本目录下「语言文件」文件夹里的 AGE3Lang_zh.txt；
     3) 点「打开」加载数据，单位列表即显示中文（如 4 - 步弓手、13 - 捕鱼船）。
   要点：
   - 文件名必须以 .txt 结尾。AGE3 只看文件名的最后一个字母是不是小写 t
     （源码 Other.cpp:401-416）：是，就按“文本语言文件”解析；不是，就当成
     language DLL 解析，于是出现乱码。所以选游戏里的 key-value.json 一定是乱码。
   - 不要用游戏自带的 ...\resources\zh\strings\key-value\key-value-strings-utf8.txt：
     那份是 UTF-8，而 AGE3 按 Windows 本地代码页（简体中文 = GBK / CP936）解码，
     会显示成“!桋熺墿鍌ㄑ”这类乱码。AGE3Lang_zh.txt 是同一内容的 GBK 版本，实测正常。
     （也就是说：这个乱码不是文件坏了，而是编码不匹配。）
   - 2026-10-04 更新：旧版 AGE3Lang_zh.txt 只由主表生成，DLC 新增的单位/科技
     （如 2306 Hero Shrine 的文本编号 421068 英雄祭坛、2312 阿耳忒弥斯 421046、
     2320 罗德岛投石手 421055）在主表里查不到编号，AGE3 就只能退回按 UTF-8 解释
     原始文本，于是这些行是乱码。新版已把同目录 13 个字符串表（主表 + paphos +
     各战役/PDLC 表 + resources\_common）合并，共 36351 条，这些行都能正常显示。
   - 文本内部：原文里的双引号一律改写成右双引号（AGE3 的 LoadTXT 遇到双引号会把
     该行截断），反斜杠与换行按 AGE3 规则转义；已按 AGE3 的解析逻辑逐条回读核对，
     36351 条全部一致。
   - AGE3Lang_en.txt 是同一份数据的英文对照版，需要英文名称时可用。

三、备份与还原
   原始文件备份：AdvancedGenieEditor3.exe.bak、AGE3NamesV0007.ini.en.bak
   还原命令（务必先关闭 AGE3）：
     Copy-Item "AdvancedGenieEditor3.exe.bak" "AdvancedGenieEditor3.exe" -Force
     Copy-Item "AGE3NamesV0007.ini.en.bak" "AGE3NamesV0007.ini" -Force

四、仍显示英文的地方
   1) 界面标签（实测 9 条，有意保留）
      - ID、SLP：通用技术缩写，中文用户同样一看就懂；而且 ID 所在槽位只有 2~3 字节，
        放不下“编号”两个字，强行改会造成截断。
      - = 、dirpicker、filepicker、panel：程序内部名称（不是给用户看的文字），
        翻译后会显示成乱码，故保留原样。
      - Default IME、MSCTFIME UI、Internet Explorer：Windows 输入法与系统窗口自带的
        文字，不属于本程序，无法也不需要汉化。
   2) 因内存窗口太小而无法译的 11 条短串（客观限制）
      程序里还有 11 条极短字符串，紧邻的下一个被引用字符串把它们能用的空间压到
      3~4 字节，装不下任何中文（一个汉字 2 字节 + 结束符）。也就是说，改它们就必然
      破坏相邻字符串，所以只能保持英文：
        ID（两处，不同地址）、Map、EF、 ID、AoE、RoR、AoK、Age、CC、TC
      这些是模块名 / 简称，在界面上出现频率很低。
   3) 程序内部与第三方库字符串（约 670 条，保留英文）
      包括 wxWidgets / libpng / boost 的断言与错误信息、C++ 函数与符号名、版本号、
      配置项缩写（MinCT、MaxR、BTSTID 等）。这些不是给普通用户看的界面文字，
      译成中文反而无法在搜索引擎与源码里对应，故保留原文。
   4) “关于”对话框中的库名与许可证简称（wxWidgets、boost、SFML、lz4、LGPLv2、GPLv3）
      按行业惯例保留原文，便于对照官方许可证；其说明文字（贡献者、使用的库）已译成中文。

五、编码说明（重要，改文件前必读）
   本程序按 Windows 本地代码页（简体中文 = GBK / CP936）解释界面字符串，
   因此译文必须以 GBK 写入；若写成 UTF-8，界面会显示“澶嶅埗”这类乱码。
   修改本程序的任何字符串，都必须保证：文件大小不变、右侧保留 NUL 结束符、
   且不覆盖紧邻的其它被引用字符串。
